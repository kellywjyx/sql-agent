# V13: SQL-ready, question-relevant column notes

Frozen on 2026-09-14, after [V12](V12-RESULTS.md) and before any V13 model run.

## Motivation

V12 stopped at its development gate. The diagnosis pointed at the note **format**, not the idea of value grounding:
- **Unquoted table-qualified names:** notes printed names like `district.A3` and `frpm.Enrollment (K-12)`, which the model copied into aliased or unquoted SQL, producing new `schema_mismatch` and parse errors.
- **Truncation:** 110 of 200 notes hit the 6,000-byte cap.
- **Irrelevant columns:** notes covered every column instead of those relevant to the question.

## The only change

V13 notes (`sql_agent.v12_notes.column_notes_v13`, version `sql-v13-column-notes-v1`):

1. **SQL-ready identifiers.** Each column is written exactly as it must appear in SQLite, double-quoted when the name is not a simple identifier. The table is named separately (``- "Enrollment (K-12)" in table frpm: …``), never as `table.column`.
2. **Question relevance.** A column is included only if its name or BIRD description shares a term of three or more characters with the question plus evidence, or if one of its stored categorical values appears in the question as a whole word.
3. **Matching stored values.** When a stored value matches a question literal, that exact stored spelling is shown instead of generic examples.
4. **Budget.** Notes are capped at 3,000 bytes, and the number of dropped entries is recorded as `notes_truncated`.

Everything else is identical to V12:
- the five V12 conventions
- the frozen V5 generation path (correction loop, JSON schema, value hints, coverage checks)
- the model `qwen2.5-coder:7b-instruct` at digest `dae161e27b0e…`
- the read-only policy, the 10-second deadline, and the Modal A10G runtime

## Data and gates

The data and gate thresholds are the same as V12:
- **Development:** V6 development split, 200 cases. The winner is the V13 arm with the highest EX that meets all of:
  - EX at least control + 0.03
  - completion no more than 0.02 below control
  - p95 latency at most 2× control
  - zero database changes
- **If no arm qualifies:** V13 stops.
- **Final:** V6 locked holdout, all 1,033 cases, opened once, control vs winner. Promotion requires all of:
  - paired database-grouped delta at least +0.03, with the 95% interval lower bound above 0
  - completion no more than 0.02 below control
  - p95 latency at most 2× control
  - zero database changes
  - gold self-consistency at least 0.99

## Disclosed risk

The development set was already used to select in V12. Choosing a V13 format after seeing V12's development failures adds selection risk on that set. The locked final remains unopened and is the unbiased test; no V13 claim is made from development numbers alone.

Cloud spend cap: $15 across V12 and V13 combined.
