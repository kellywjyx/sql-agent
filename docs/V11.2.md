# V11.2: token-length correction

Recorded on 2026-09-14, after V11.1 pilot training and before any V11.2 job.

## What V11.1 found

Both V11.1 pilot recipes finished one epoch with finite training loss (A 0.248, B 0.229) in about 270 s each on an A100-40GB. Both then stopped at the frozen finite-loss check because validation `eval_loss` was NaN. No pilot adapter was saved. The runs are kept unchanged under `/artifacts/v11/sql-agent/training/pilot/` on the Modal volume and in `artifacts/v11/compute/modal-ledger.json`.

**Root cause:** `sql_agent.v11_data._token_count` called `len()` on the value returned by `tokenizer.apply_chat_template(..., tokenize=True)`. In Transformers 4.57 that value is a `BatchEncoding` dict, so every example measured **2** tokens, which is also the `token_count` recorded in the frozen metadata. The frozen claim that 100% of inputs fit 2,048 tokens was therefore wrong. Recounted with the pinned tokenizer (prompt plus reference SQL):

| Role | Examples | Over 2,048 tokens | Prompt alone ≥ 2,048 | Max |
|---|---:|---:|---:|---:|
| Train | 1,200 | 121 (10.1%) | 102 | 2,900 |
| Validation | 150 | 42 (28.0%) | 42 | 2,398 |
| Development | 200 | 0 | 0 | 1,512 |

Validation examples whose prompt fills the window have no completion tokens left, so the completion-only loss divides by zero.

## What changes in V11.2

- `_token_count` reads `input_ids`, with tests in `tests/test_v11_token_count.py`.
- Training `max_length` rises from 2,048 to **3,072** (`v11_training.MAX_LENGTH`), which covers every example. `TRAINING_VERSION` becomes `sql-v11.2-qlora-v1`.
- V11.2 artifacts are written to a separate tree, `/artifacts/v11.2/` on the Modal volume and `artifacts/v11.2/` locally. Model files, frozen data, and the scorer are copied into it server-side.

## What does not change

- Frozen datasets and their hashes: examples are not filtered or rewritten.
- Model revision, recipes A and B, seed, LoRA configuration, and every model-quality gate in `v11_selection.py`.
- The inference runtime and its 2,048-token input guard. No development prompt exceeds 1,512 tokens, so the valid V11.1 base pilot evaluation (EX 0.383, completion 0.85, run `20260914T055443.289979Z-43f4330b`) is reused unchanged in the V11.2 tree.
- The V11.1 hardware amendments: Modal A100 training, A10G evaluation, and the 36 GiB peak-allocation limit. Peak memory at 3,072 tokens is recorded in each `training.json`.
