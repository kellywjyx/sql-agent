# V11 direct QLoRA generator adaptation

V11 tests whether direct, grounded SQL supervision can improve candidate quality after V10's selective detector produced no interventions. It adapts the official Apache-2.0 `Qwen/Qwen2.5-Coder-7B-Instruct` revision `dcc04bb77301e6368aa24a609c6ea496b70503e8` with CUDA-only NF4 QLoRA. The public default stays at V5 unless all downstream gates pass.

## Frozen data protocol

Seed `20260923` assigns whole databases to roles. Starting from 9,428 local BIRD training records across 69 databases, preparation excludes all V5 holdout databases, prior V3–V10 exposures and near-duplicate groups, and duplicate normalized questions or SQL. The selected roles contain:

| Role | Databases | Cases | Dataset identity |
|---|---:|---:|---|
| Training | 45 | 1,200 | `aac84867758666186eddf87910a174d5635d173757213e53beeac1a9c7a99dd9` |
| Validation | 6 | 150 | `d8eba72d9e8c80e089d6970c0b66521fa6ee523a591581cb20374834d52c4e0f` |
| Development | 7 | 200 | `2fdd8978849f3eb9bdc66aa0042cfaee0e48fbc8e2868572fb4c07b8d81b8680` |

All selected inputs fit within 2,048 tokens without truncation. Inputs contain the frozen system instruction, question, auto-selected schema, and V9 scoped generated evidence. Targets contain only gold SQL. Human BIRD evidence is not present in model inputs. The V5 200-case set remains inspected regression material, and the 1,033-case locked final remains unopened.

## Runtime and gates

The isolated environment pins PyTorch 2.8.0 CUDA 12.8, Transformers 4.57.6, TRL 0.25.1, PEFT 0.18.1, bitsandbytes 0.49.2, and Accelerate 1.10.1. The configuration uses NF4 with double quantization and BF16 compute, rank 8, alpha 16, dropout 0.05, all linear modules, completion-only loss, gradient checkpointing, paged 8-bit AdamW, batch size 1, accumulation 16, and one epoch.

The eight-example preflight requires CUDA-only model placement, at least 7 GiB free VRAM before model load, no CPU or disk offload, at most 7.6 GiB peak allocation, finite loss and gradients, a projected 1,200-case duration no longer than 2.2 hours, and a fresh-process adapter reload. Failure ends V11 without a 3B fallback.

## Implemented interfaces

- `v11-download-model`, `v11-verify-asset`, data preparation, evaluation-input preparation, preflight, reload, pilot/full training, evaluation, and comparison CLI paths.
- `pipeline_profile="v11_adapter"`, enabled only when `SQL_V11_ADAPTER` points to a local adapter with a manifest.
- Base revision, adapter identity, dataset identity, recipe, and inference backend metadata.
- Immutable compute ledger and run directories under `artifacts/v11/`.
- Frozen evaluation messages reused verbatim during inference to prevent prompt drift.

The existing SQLGlot validation, read-only URI, authorizer, extension and attachment denial, changing-time denial, 256-column schema policy, 64-column result policy, deadlines, and row/byte limits remain unchanged.

## Boundary

No API, correction model, multi-candidate generation, model offload, merged weights, GGUF conversion, public adapter, or locked-final evaluation is part of V11.
