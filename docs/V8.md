# SQL Agent V8: database-grounded evidence reconstruction

## Scope

V8 asks how much of BIRD's human evidence benefit can be reconstructed from the
database package without exposing gold SQL or oracle evidence at inference. It
uses only 40 already exposed V7 reproduction cases. The 1,033-case locked final
remains unopened.

The production path is deliberately simple:

```text
SQLite schema + descriptions + values -> offline knowledge cache
question -> typed evidence routers -> confidence filter -> <=4 KB / 12 facts
question + schema + evidence -> Arctic Q4 -> guarded SQLite execution
```

Qwen V5 remains the public default. V8 is an evaluation-only specialist path.
It uses one Arctic Q4 candidate, no critic, selector, repair model, Talon, Q5,
API, or multi-agent generation.

## Offline cache and trust boundary

`KnowledgeCache` identifies an artifact by the source database bytes, canonical
schema, database descriptions, cache version, and normalization version. It
stores whole-column SQLite type/null/distinct counts, native numeric ranges,
all values for columns with at most 100 distinct values, the 25 most frequent
values for larger columns, token/trigram indexes, storage-pattern summaries,
and exact foreign keys. Missing high-cardinality literals may use at most four
one-second parameterized read-only probes.

The source connection uses read-only URI mode, `query_only`, disabled extension
loading, the existing authorizer, and a byte-hash check before and after cache
construction. Cache artifacts live outside source control. Names, descriptions,
and values remain untrusted prompt data.

Cache v2 distinguishes native SQLite numeric storage from numeric-looking TEXT;
only the latter can emit a `numeric_text_cast` fact. This correction was made
after the frozen V8 model campaign and therefore has offline coverage but no
claimed EX result.

Evidence is a typed Pydantic object before rendering. Routes are separated into
literal values, database descriptions/encoded categories, normalization and
numeric/storage facts, and joins. Facts record their source, confidence,
database identifier, printed value, transformation, and support. Oracle evidence
is present only in scoring-side decomposition artifacts.

## Frozen gates

The exposed 40 cases were decomposed as 9 evidence-limited (A), 12 evidence
unnecessary (B), 19 reasoning-limited (C), and 0 oracle-harmful (D). The CPU
retrieval gate on A required literal recall >=0.60, value-to-column accuracy
>=0.80, and evidence precision >=0.70. A 20-case pilot then required at least
+0.075 EX over the matched no-evidence control and more recoveries than
regressions. Only a passing pilot winner could run on all 40 exposed cases.

The broader run used the same continuation rule. A failed broader gate stops V8;
it cannot open the locked final or change the public default.

## Interfaces

The V8 cache is inspectable without invoking a model:

```powershell
sql-agent build-v8-knowledge --artifacts artifacts\v8 --database path\db.sqlite
sql-agent inspect-v8-evidence --artifacts artifacts\v8 --database path\db.sqlite `
  --v8-evidence-mode all --question "Which private schools ...?"
```

Campaign commands and measured results are in [V8 results](V8-RESULTS.md) and
[reproduction instructions](REPRODUCE.md). These experiments are not an official
BIRD submission.
