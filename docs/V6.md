# V6 SQL-specialized generation and semantic verification

V6 adds local SQL-specialized generation without changing the V3 read-only execution policy. It is a local portfolio experiment, not an official BIRD submission. SQL-specialized checkpoints may have trained on BIRD training or development material, so development scores measure engineering behavior on this frozen local protocol rather than unbiased generalization.

## Implemented path

The application now supports:

- an M-Schema renderer with exact identifiers, SQLite types, primary and foreign keys, descriptions, join neighbours, storage profiles, and bounded relevant values;
- checksum-addressed, read-only value profiles covering SQLite storage types, null rates, bounded distinct counts, numeric ranges, low-cardinality categories, and common numeric/date formats;
- model adapters for the frozen Qwen V5 control, Qwen with M-Schema, Arctic-Text2SQL-R1-7B, and the gated XiYanSQL fallback;
- direct and plan-first prompt forms with natural questions and BIRD evidence kept in separate, untrusted sections;
- SQLGlot semantic checks for projections, literals, comparisons, joins, aggregation, grouping, distinctness, ordering, limits, ratios, and numeric-text cleanup;
- bounded candidate generation and deterministic selection metadata, with `needs_review` when mechanical evidence cannot distinguish candidates;
- immutable pilot/development/final datasets, model-job accounting, final-set locking, database byte hashes, and grouped final-report tooling.

Existing requests remain valid. Optional API/CLI fields are `model_profile`, `generation_strategy`, `value_mode`, and `prompt_style`. Responses retain SQL, rows, attempts, termination, policy, schema selection, and question plan, and add candidates, selection reason, semantic checks/risk, review state, schema format, and value-profile identity.

## Campaign commands

The commands below require the already prepared local BIRD files. Expected SQL remains accessible only to scoring code.

```powershell
.venv\Scripts\python.exe scripts\prepare_sql_v6.py --artifacts C:\path\to\artifacts
.venv\Scripts\python.exe scripts\run_sql_v6_job.py --job-id v6-pilot-qwen-v5 --stage pilot --mode qwen_v5 --estimate-seconds 300 --reserve-seconds 6840
.venv\Scripts\python.exe scripts\run_sql_v6_job.py --job-id v6-pilot-arctic-direct --stage pilot --mode arctic_direct --estimate-seconds 420 --reserve-seconds 6840
.venv\Scripts\python.exe scripts\select_sql_v6.py freeze-selection --artifacts C:\path\to\artifacts
```

`run_sql_v6_job.py` refuses a job whose estimate would consume the frozen final reserve or exceed the 14,400-second SQL-agent budget. See [V6 results](V6-RESULTS.md) for the measured budget stop.

## Security boundary

All generated SQL still passes statement validation and executes through a SQLite read-only URI plus authorizer in a bounded worker. Attachments, extensions, writes, changing-time functions, more than 256 schema columns, more than 64 result columns, timeouts, and row/byte excesses remain denied. Value profiling uses the same read-only executor and never enumerates high-cardinality columns.
