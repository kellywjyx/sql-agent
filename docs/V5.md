# V5 hybrid schema retrieval and semantic review

## Scope

V5 is a local portfolio experiment over internal BIRD training subsets. It is not an official BIRD submission or leaderboard result. All application inference uses local Ollama models; schema embeddings run on CPU; API cost is $0.

The V5 campaign has a fixed 6,300-second (1.75-hour) model-job ledger. Pilot-dominated candidates stop before the 100-case development capture. The development winner is frozen before the new locked 200-case holdout is opened.

## Retrieval pipeline

Each table and column becomes a searchable document containing its exact SQLite identifier, type, key role, neighboring tables, and available BIRD description text. The cache identity hashes the canonical inspected schema, descriptions, embedding model, and pinned model revision. Normalized BGE vectors are stored outside source under `artifacts/sql-agent/schema-index/<schema-identity>/`.

Selection uses reciprocal-rank fusion over exact identifier, description, token-overlap, and BGE cosine rankings. Exact matches are retained first. The prompt contains at most 32 retrieved columns plus primary/foreign keys and shortest connecting foreign-key paths. Databases with at most 40 columns retain all columns, with relevant columns ordered first. The final prompt remains bounded to 10 KB.

No gold SQL or expected answer is embedded or provided to the application. Gold SQL is parsed only after capture to score table recall, valid-column recall, join-path coverage, and execution equivalence. References to columns absent from the supplied SQLite schema are reported separately rather than counted as retriever misses.

## Query review and security

The answer-free question plan describes candidate output/filter columns, aggregate and grouping intent, ordering, limit intent, and required joins. SQLGlot checks generated SQL against the plan. A successful execution, including a valid empty result, is not treated as semantic correctness.

Generation is bounded to three attempts. Duplicate normalized SQL is rejected without execution. A third generation call is allowed only if the second candidate leaves a different parser, execution, or coverage failure. Coverage diagnostics never contain gold SQL.

The V3 execution policy remains unchanged: read-only URI connections, query-only mode, authorizer checks, extension and attachment denial, changing-time denial, a 256-column SQLite schema limit, an independent 64-column result limit, deadlines, and row/byte limits. V5 records actual pre/post SQLite byte hashes; only a mismatch of those bytes fails the integrity gate.

## Reproduction

From the independent repository after setup:

```powershell
.venv\Scripts\python.exe -m sql_agent.cli index-schema --artifacts C:\path\to\artifacts --database C:\path\to\database.sqlite
.venv\Scripts\python.exe -m sql_agent.cli inspect-schema --artifacts C:\path\to\artifacts --database C:\path\to\database.sqlite
.venv\Scripts\python.exe -m sql_agent.cli ask --artifacts C:\path\to\artifacts --database C:\path\to\database.sqlite --schema-mode hybrid --question "Which products have the highest revenue?"
```

The workspace campaign command is intentionally outside the independent repository because it coordinates private frozen evaluation artifacts:

```powershell
sql-agent\.venv\Scripts\python.exe scripts\run_sql_v5_campaign.py
```

Final metrics are added only after complete immutable captures and the frozen selection gate. Interrupted or budget-limited work remains explicitly incomplete.
