# V3 correctness campaign

Implementation and offline checks are available. Final experiment results are
reported separately; passing fixture tests is not evidence of model quality.
Keep the v1/v2 artifacts. No new downloads or publication are part of v3.

## Independent local execution

Install the checksum-pinned `portfolio-llm-evals` 0.3.0 wheel using the existing
Windows setup command and `evals-dependency.json`. Use Python 3.13. The finance
training environment is separate from its UI environment.

The asset directory must contain the pinned cached models, original v2 exposure
records, and frozen v3 datasets. It can be anywhere outside the Git repository.
No parent-folder Python scripts are needed for the commands below.

```powershell
$assets = 'C:\path\to\local-assets'
.venv\Scripts\python.exe -c "from pathlib import Path; from sql_agent.v3_data import prepare; prepare(Path(r'$assets'))"
.venv\Scripts\python.exe scripts/budget_v3.py --artifacts $assets --stage pilot --mode revised_linking --estimate 180 --reserve 2500
```

Preparation is a one-time operation and refuses to overwrite frozen data. Before
calling preparation, set `HF_HUB_OFFLINE=1` and `HF_DATASETS_OFFLINE=1` in PowerShell
(`$env:HF_HUB_OFFLINE='1'`; `$env:HF_DATASETS_OFFLINE='1'`). Existing manifests record
the exact cached revisions and exclusions. Never regenerate a holdout after
viewing its answers. Expected values are read only in preparation/scoring.

Modes: `revised_linking, reviewed`. Stages: pilot, development, final
.
The estimate and final reserve are required planning inputs; use measured pilot
timings. Every process shares the same cumulative ledger and GPU lease. Do not
run interactive model requests while a campaign owns that lease. A locked final
dataset requires a frozen development selection. Failed/interrupted captures
are retained and must not be silently retried or excluded from denominators.

## Evaluation interpretation

Compare only identical dataset, metric and execution-policy identities. Primary
comparisons use 2,000 paired resamples, with source-family/database grouping where
applicable. Capture completion, application failure and quality-gate status are
different fields. Prose semantic assessments are diagnostics, not source proofs.
Local API charges exclude unmeasured electricity/hardware costs.

## Release boundaries

The website retains its existing design and v2 evidence until v3 final reports
are complete. Public GitHub identity, licensing/publication review, work history,
hosted CI and reduced-motion verification remain separate release tasks.
